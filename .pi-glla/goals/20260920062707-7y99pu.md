## Objective

> ## Channelizer microservice: isolate a narrowband channel from the wideband VITA49 collection

### Current state (verified read-only)

`sigproc` is a **single-crate Rust binary** on the live k3s cluster:

- `src/main.rs` (142 L) — UHD probe/open → sc16 IQ → `Vita49Forwarder` → UDP
- `src/capture.rs` (147 L) — B210 RF config + `read_batch` (2048 samples, 0.1 s timeout)
- `src/vita49.rs` (413 L) — IF Data Packet framer + UDP forwarder with drop counting
- `src/config.rs` (82 L) — `config.toml` (device/rf/forwarding) + validation
- `src/lib.rs` (130 L) — FMA kernels (the only in-tree DSP), with tests
- `deploy/` — ConfigMap (`915 MHz / 2 MS/s / RX2`), Deployment pinned to `rpi-four-2`, kaniko Job, root `Dockerfile`

Live evidence: `deploy/sigproc` **1/1 Running** (2d), `deploy/waterfall-bridge` + `deploy/waterfall-consumer` consuming `waterfall-service:4820/UDP`, node `rpi-four-2` holds the B210. Pod logs show the existing hop-boundary failure mode in production: `VITA49 destination … still unresolved; 384000 packets dropped so far`.

So the microservice *pattern* exists for exactly one hop (`sigproc → waterfall`). This goal adds a genuine **second and third service boundary** (channelizer → in-repo sink), which is the thing the objective actually needs to prove.

### Decisions (with rationale and rejected alternatives)

**D1 — Rust workspace, one child directory per module + per-module Dockerfile.** Root becomes `Cargo.toml [workspace]` with flat module dirs: `common/` (lib crate `sigproc-common`), `capture/` (bin `sigproc` — **binary name preserved** so `ghcr.io/rodoyle/sigproc:latest` and the mounted `config.toml` keep working), `channelizer/`, `fixture/`, `sink/`. Each has its own `Dockerfile`; the root `Dockerfile` moves to `capture/Dockerfile` and the kaniko Job is updated to `-f capture/Dockerfile`. *Rejected:* keeping a single crate (VITA49 framing would duplicate across services — the wire format is the contract and must be single-sourced), and a `crates/` nesting (the operator asked for module-as-child-dir).

**D2 — Transport stays VITA49 UDP unicast, point-to-point.** Reuses the existing framer and the format the sibling `waterfall` image already parses; zero new dependencies. *Rejected:* UDP multicast (needs a multicast-capable CNI on flannel/k3s — real infra risk for no gain at one consumer) and NATS/JetStream (a broker to operate, and it would force a rewrite of the working `sigproc → waterfall` path).

**D3 — Channel plan: 915 MHz + 200 kHz offset, unchanged live capture.** The live `sigproc`/waterfall stream is not touched, so there is no existing-deployment behavior change and no rollback needed. *Rejected:* retuning to ~120 MHz airband (real intelligible AM voice, but it blinds the waterfall UI to ISM and needs a ConfigMap change + rollback), and B210 RX channel 1 for airband (best of both, but needs a channel-index option, a second Deployment and a second antenna — deferred to a queued item).

**D4 — Decimation factor is integer-only, so the default output rate is 50 kS/s, not 48 kS/s.** 2 000 000 / 48 000 = 41.667: a non-integer ratio would require a multi-stage rational resampler (÷25 → 80 kS/s → ×3÷5) in the *first* milestone, which is DSP risk in the wrong place. ÷40 gives exactly 50 kS/s from one integer stage. `output_rate` and `decimation` are config-driven and **validated at load** (`sample_rate / decimation` must be integral, else fail fast). If a 48 kHz artifact is ever required, the deferred demod item adds a 50k→48k resample. *Rejected:* 40 kS/s (÷50, narrower than needed and an odd rate) and 48 kS/s now (unnecessary resampler complexity before the plumbing is proven).

**D5 — Hop failures: drop + count + explicitly mark discontinuity.** Keeps the proven precedent (never block upstream, count drops) *and* fixes its real defect: silently spliced output that could make a later tone assertion pass across a corrupted region. The `sigproc-common` receive path owns a sequence-gap tracker; every module surfaces `..._packets_dropped_total` and `..._seq_gaps_total` on `/metrics`, and any module writing a file artifact records gaps in its sidecar JSON. *Rejected:* bounded buffer + upstream backpressure (eventually stalls or drops anyway, and it would change live capture behavior) and counters-only (silent corruption).

**D6 — Deterministic fixture, injected through a `replay` input mode.** `channelizer --input=udp|replay --file=…`; the code path after the VITA49 receive boundary is identical, so **the DSP is never mocked**. The fixture is generated in-cluster by an initContainer from the `fixture` image into a shared `emptyDir` (a 1 s 2 MS/s fixture is ~8 MB — too large for a ConfigMap). *Rejected:* a separate `sigproc-sim` producer service (truest four-hop path but adds a whole test-only image + Deployment) and local-fixture-only (reduces the cluster assertion to "something arrived").

**D7 — The gate's consumer is an in-repo `vita49-sink` binary run as a Job.** It binds the narrowband UDP port, parses VITA49 with the common crate, and prints one JSON verdict line (`ok`, `packets`, `rate_hz`, `seq_gaps`, `decoded_hz`). Fully in-repo, deterministic, greppable, and it doubles as the narrowband wire-format contract test. *Rejected:* a second `waterfall-consumer` instance (real downstream evidence, but it couples the gate to that image's CLI and publishes to the bridge) — available later as human-facing evidence.

**D8 — Artifacts on PVC/emptyDir; RustFS is delegated, not built.** The `rustfs` namespace exists but is **empty** (an empty `rustfs-credentials` Secret only — no Service, no Deployment), so S3 would mean a cross-repo request plus an SDK dependency. Per repo boundary rules this session does not write to `infra`; RustFS becomes a queued, intercom-delegated item.

### Risks & failure modes

- **cargo-chef over a workspace + kaniko on arm64** — the recipe step needs every member manifest copied before `cargo chef prepare`, or dependency resolution silently degrades to a full rebuild-and-fail. *Mitigation:* copy all module `Cargo.toml`s and `Cargo.lock` explicitly; verify the image builds before touching the live Deployment, and keep the previous `sigproc` image digest recorded for rollback.
- **Filter/NCO state across VITA49 packet boundaries** — per-packet state reset injects phase discontinuities that show up as tone error, i.e. a false pass/fail. *Mitigation:* persistent state plus the packet-size-invariance test (same IQ in 2048/333/1-sample chunks → identical output).
- **Dropped packets silently splicing output** — a tone assertion could pass across a corrupted region. *Mitigation:* D5 gap marking, and the gate asserts `seq_gaps == 0` rather than only checking the tone.
- **Live capture behavior change** — image/name/config regressions would break the working waterfall stream. *Mitigation:* binary name `sigproc`, config schema and `SIGPROC_CONFIG`/`--dry-run` CLI contract frozen; `--dry-run` and existing framing tests as explicit regression gates.
- **Empty ISM band** — no 915 MHz device to press means the OTA observation shows nothing. *Mitigation:* the fixture gate is authoritative; the OTA gate is best-effort and documented as such, never a pass/fail blocker.
