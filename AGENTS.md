## Rules
1. Public Rust wide-band software-defined radio project. always cargo clippy and cargo format. Priority target is linux arm64 SBCs and x86_64 K8s hosts.
2. Mono-repo. Each Rust service is a top level folder based on `common`. `deploy` contains k8s deployment artifacts. `test` is for end-to-end (python) test scripts.
3. Code is lightweight and very performance sensitive, especially the Vita49.2 UDP multicast critical path (capture --> channelizer --> demod|waterfall|sink). CPU-specific optimizations, SIMD, and instrinsics *are* encouraged. Target throughput is 16-bit I, 16_bit Q at 60 MSPS over gigabit+ ethernet. 
4. The sister projects github.com/rodoyle/waterfall (public) and github.com/rodoyle/infra (private) define the Web UI and host k8s platform respectively. You should use the pi-intercom skill to interogate the agents that own these repositories, but do not make changes there yourself.
5. The `capture` service must link against the UHD SDR control library. It unlikely present locally and is hard to build/test. Instances have exclusive control over the RF front end. It should be kept as thin as possible translating commands to UHD calls, board control, and shipping complex baseband I/Q samples - that is all. It is pinned to a specific node. Build and Test loops should leverage the github runners, in-cluster kaniko jobs (./scripts/trigger-rc-build.sh, ./deploy)
6. Execution of all `kubectl` commands should be delegated via:pi-intercom to the infra agent or escalated to human user. Use escalate, generate a script or yaml manifest and prompt user with `[Action Required]` to flag actions for human follow up.
7. Use the `./docs` folder for long-term and scratch docs. Plans larger than a single glla goal should go in `.docs/plans` with yaml front matter capturing the date and any dependencies.
